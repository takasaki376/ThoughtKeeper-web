## 適用範囲

- スコープ: `tasks/` ディレクトリ以下のドキュメント。
- 強制対象: `tasks/10_ops_admin_dashboard_and_roles.md`（本規約に完全準拠）。
- 任意適用: 他の `tasks/*.md` も同形式を推奨。

## 見出しと順序（必須）

以下のセクションをこの順で配置してください。見出しは日本語、半角スラッシュを含む表記・句読点を原文どおりに維持します。

1. `# タスク: <タイトル>`（先頭に 1 個の `#`、接頭辞「タスク: 」を含む）
2. `## 目的 / ゴール`
3. `## スコープ`
4. `## 成果物`
5. `## 実装タスク`
6. `## 受け入れ条件（DoD）`
7. `## 留意点 / リスク`

各セクションの直下は箇条書き（ハイフン `-`）またはチェックリスト（`- [ ]`）を基本とし、段落テキストは使用しません（説明が必要な場合も 1 行完結を推奨）。

## 箇条書き・チェックリストの書式（必須）

- 箇条書きは `- `（半角スペース 1 つ）で開始し、1 項目は原則 1 行に収めます。
- ネストは必要最小限。ネストする場合は 2 スペースでインデントし、同じく `- ` を用います。
- チェックリストは `- [ ] ` で未完了を示します。
- 実装タスクの大項目は次の形式に従い、見出し化せずに番号付き行 → チェックリストの順で記述します。
  - 例: `1) Ops ダッシュボードのシェル` の直後に改行し、`- [ ] ...` を複数行で列挙。

## 実行記録ルール（参照タスクの x マーク）

- `tasks/` 配下の他ドキュメントを参照してタスクを実行する場合、参照一覧をチェックリストとして明記します（例: `- [ ] tasks/09_ops_admin_signup_screen.md`）。
- その参照タスクを実行したら、対象項目を `- [x]` に更新して実行済みを示します。
- `- [x]` の使用は「参照した `tasks/*.md` の実行状況」に限定します。一般の未完了/完了管理は原則 `- [ ]` を用い、本文内で「完了」と記述しないでください。
- 実行日時や担当者を追記する場合は末尾に括弧で付記します（例: `- [x] tasks/10_ops_admin_dashboard_and_roles.md（2025-10-29 by ops）`）。

## インラインコード・パス・コマンド（必須）

- リポジトリ内のパス、ルート、ファイル名、型名、関数名、SQL、コマンドは必ずバッククォートで囲みます（例: `` `src\app\(authenticated)\MemoEditor\page.tsx` ``、`` `/MemoEditor` ``、`` `isOpsAdmin` ``、`` `yarn build` ``）。
- 短い SQL はインラインコードで 1 行に収めます。複数行の SQL が必要な場合のみ三連バッククォートのコードブロックを使用します。
- URL パラメータやクエリもインラインコードで表記します（例: `` `/ops/signup?error=membership_failed` ``）。

## 文体・表記（必須）

- 言語は日本語。技術用語・識別子は英語で原綴維持。
- 句読点・括弧は既存文書に合わせ、全角の使用を許容します（例: `受け入れ条件（DoD）`）。
- 半角英数字、スラッシュ、アンダースコア、ハイフンは変更しないでください（`ops_signup` など）。
- 1 行 120 文字を超えない範囲で改行を入れても構いませんが、箇条書き 1 項目は 1 行完結を基本とします。

## 禁則事項

- 見出し名・順序の変更禁止（上記順序を厳守）。
- 箇条書きの先頭記号変更禁止（`-` に統一、`*` や数字ピリオドは使用しない）。
- 一般の箇条書き・チェックリストで `✅` 等の絵文字を使わない（`- [ ]` / `- [x]` のみ）。
- `- [x]` は「参照した `tasks/*.md` の実行状況」以外には使用しない。
- 英訳や用語の言い換えによる意味の変質を行わない。

## 雛形テンプレート（再利用可）

以下のテンプレートをベースに内容を更新してください。セクション名と基本構造は維持します。

```

## 目的 / ゴール
- <1 行で要点>
- <1 行で要点>

## スコープ
- 画面: `<route>`（Server/Client を明記）
- 認可: `<module or function>`
- コールバック: `<path>` の分岐
- DB: `<migration file>` と主要テーブル
- ナビゲーション（任意）: `<方針>`

## 成果物
- ページ: `<path>`（<要点>）
- ルール: `<module>`（<要点>）
- コールバック: `<path>`（<遷移条件>）
- マイグレーション: `<migration file>`
  - `<table definition or brief>`
- テスト: `<paths>`（<観点>）
- ドキュメント（任意）: `<path>`

## 実装タスク
1) <大項目名>
- [ ] <チェック項目>
- [ ] <チェック項目>

2) <大項目名>
- [ ] <チェック項目>

3) DB マイグレーション
- [ ] `<migration file>` を追加
  - `create table if not exists <table>(...);`
- [ ] `<seed file>` を更新（任意）

4) ナビゲーション（任意）
- [ ] <チェック項目>

5) テスト
- [ ] <観点>

6) 品質/整備
- [ ] `yarn lint`
- [ ] `yarn build`

## 受け入れ条件（DoD）
- <1 行で検証可能な条件>
- <1 行で検証可能な条件>

## 留意点 / リスク
- <運用・技術的リスク>
```

運用: 本規約に反する変更を提案する場合は、まず `tasks/AGENTS.md` を更新し、変更理由と影響範囲を明記してください。より深い階層に配置された AGENTS.md がある場合は、そちらを優先します。
